Séquence 01

Situation de départ : pourquoi organiser les données ?

•Cours

Une organisation peut gérer un grand nombre d'informations : personnes, activités, rendez-vous, équipements, paiements, incidents, etc. Lorsque ces informations sont réparties dans plusieurs fichiers ou documents, leur recherche devient lente et leur mise à jour peut produire des contradictions.

Une même information enregistrée à plusieurs endroits peut, après une modification, rester ancienne dans certains fichiers. On obtient alors des données incohérentes. Une solution consiste à organiser les informations dans une base de données.

Fichier patientsAgenda médecinsFeuille consultationsNotes diverses
→
BASE DE DONNÉESinformations organisées et cohérentes

✓À retenir

Une base de données répond à un besoin d'organisation, de recherche et de mise à jour cohérente des informations.

✍️À toi de jouer

Un centre médical travaille encore avec quatre fichiers séparés. Parmi les difficultés suivantes, relève celles qu’une base de données peut aider à résoudre :

  1. Le téléphone d’un patient n’est pas le même dans deux fichiers.
  2. Retrouver toutes les consultations d’un patient prend beaucoup de temps.
  3. L’imprimante du secrétariat manque de papier.
  4. Le nom et l’adresse d’un patient sont recopiés plusieurs fois.
  5. Deux documents donnent des informations contradictoires sur un même rendez-vous.
✓ Vérifier ma réponse

Les difficultés 1, 2, 4 et 5 concernent l’organisation et la cohérence des données. Le manque de papier de l’imprimante n’est pas un problème de base de données.

⚠️Attention

Ne pas présenter la base de données comme un simple « fichier plus grand ».

Séquence 02

Définition et utilité d'une base de données

•Cours

Une base de données (BD) est un ensemble organisé de données relatives à un même domaine. Elle permet d'enregistrer, consulter, mettre à jour et exploiter ces données selon les besoins.

Exemple : dans le domaine d'un centre médical, une base peut mémoriser les patients, les médecins et les consultations.

✓À retenir

BD = données organisées relatives à un même domaine.

✍️À toi de jouer

Quels ensembles de données peuvent former une base cohérente autour d’un même domaine ?

A. Patients — médecins — consultations. B. Patients — météo de Tunis — résultats de football. C. Salles — postes informatiques — pannes. D. Chambres d’hôtel — recettes de cuisine — satellites.

✓ Vérifier ma réponse

A et C. Chaque ensemble concerne un même domaine de gestion.

⚠️Attention

Ne pas confondre une base de données avec le logiciel qui la gère.

Séquence 03

Définition et rôle du SGBD

•Cours

Un SGBD (Système de Gestion de Base de Données) est un logiciel qui permet de créer et de gérer une base de données. Il permet notamment de définir sa structure, ajouter/modifier/supprimer des données, rechercher des informations et appliquer des contraintes d'intégrité.

La base de données contient les données ; le SGBD est le logiciel qui permet de les gérer.

🗃️Base de données

Contient les données organisées.

↔
⚙️SGBD

Logiciel qui crée, gère, recherche et contrôle ces données.

✍️À toi de jouer

Classe chaque proposition dans la bonne catégorie : BD ou SGBD.

  • contient la date d’une consultation ;
  • permet d’ajouter un patient ;
  • mémorise le nom d’un médecin ;
  • contrôle une règle de cohérence ;
  • conserve la spécialité d’un médecin.
✓ Vérifier ma réponse

BD : date d’une consultation, nom d’un médecin, spécialité. SGBD : ajouter un patient, contrôler une règle de cohérence.

⚠️Attention

Dire « MySQL est une base de données » sans préciser qu'il s'agit d'un SGBD.

Séquence 04

Base de données relationnelle

•Cours

Une base de données relationnelle (BDR) organise les données dans des tables liées entre elles. Chaque table regroupe des données relatives à un même sujet. Les liens permettent de rapprocher les informations de plusieurs tables sans répéter inutilement les mêmes données.

PATIENT
  • IdPatient
  • Nom
  • Prenom
  • DateNaissance
CONSULTATION
  • IdConsultation
  • DateConsultation
  • HeureConsultation
  • Motif
  • IdPatient#
  • IdMedecin#
MEDECIN
  • IdMedecin
  • Nom
  • Prenom
  • Specialite
PATIENT ↔ CONSULTATION 1 → plusieursMEDECIN ↔ CONSULTATION 1 → plusieurs

◈Exemple

Règles : - chaque consultation concerne exactement un patient ; - chaque consultation est assurée par exactement un médecin ; - un patient peut avoir plusieurs consultations ; - un médecin peut assurer plusieurs consultations.

Tables : PATIENT, MEDECIN, CONSULTATION.

✍️À toi de jouer

Dans le centre médical, pourquoi serait-il mauvais de recopier le nom, le prénom et la date de naissance du patient dans chaque consultation ? Donne deux raisons.

✓ Vérifier ma réponse

Cela répéterait inutilement les mêmes informations et pourrait produire des incohérences lors d’une modification. La table CONSULTATION doit référencer PATIENT plutôt que recopier ses informations.

⚠️Attention

Dans le vocabulaire de ce cours, relation désigne un lien entre tables ; ne pas l'utiliser comme synonyme de table.

Séquence 05

Structure d'une table : table, champ, enregistrement, valeur

•Cours

Une table possède un nom et regroupe les données relatives à un même sujet.

Un champ représente une information à mémoriser. Dans une représentation en tableau, un champ correspond à une colonne.

Un enregistrement regroupe les valeurs décrivant un élément enregistré. Dans une représentation en tableau, un enregistrement apparaît sur une ligne.

Une valeur est le contenu d'une case, située à l'intersection d'un champ et d'un enregistrement.

TABLE : PARTICIPANT
IdParticipantNomPrenomTelephone
P014MansourInes22123456
P015TrabelsiYoussef50112233
Champ / colonne Enregistrement / ligne Valeur

◈Exemple

PARTICIPANT(IdParticipant, Nom, Prenom, Telephone).

Exemple d'enregistrement : P014 | Mansour | Ines | 22123456.

  • table : PARTICIPANT ;
  • champ : Nom ;
  • enregistrement : toute la ligne P014 ;
  • valeur : Mansour.

✍️À toi de jouer

Dans la table PARTICIPANT ci-dessus, indique :

  1. le nom de la table ;
  2. deux champs ;
  3. l’enregistrement du participant P014 ;
  4. la valeur du champ Nom pour P014.
✓ Vérifier ma réponse
  1. PARTICIPANT. 2. Par exemple IdParticipant et Nom. 3. P014 | Mansour | Ines | 22123456. 4. Mansour.

⚠️Attention

Ne pas présenter « colonne » comme le terme principal du modèle : le vocabulaire du cours reste champ ; colonne sert d'aide visuelle.

Séquence 06

Propriétés d'un champ : rappel de 3e année

•Cours

Un champ est défini notamment par : - son nom ; - la nature des valeurs qu'il peut contenir (type) ; - lorsque cela est nécessaire, sa taille ; - les contraintes que ses valeurs doivent respecter.

Exemples : - DateConsultation contient une date ; - Telephone contient une donnée respectant le format prévu par le système ; - Capacite d'un atelier doit respecter une règle numérique définie.

✍️À toi de jouer

Pour chaque règle, précise si elle concerne surtout le type, la taille ou une contrainte du champ.

A. DateConsultation doit contenir une date. B. CodeSalle ne dépasse pas 5 caractères. C. Capacite doit être comprise entre 5 et 30. D. Etat doit appartenir à {En service, En panne, Maintenance}.

✓ Vérifier ma réponse

A → type. B → taille. C → contrainte. D → contrainte.

⚠️Attention

Ne pas introduire ici la syntaxe SQL des types ou contraintes ; elle appartient au chapitre suivant.

Séquence 07

Clé primaire simple

•Cours

Une clé primaire est un champ ou un ensemble de champs qui permet d'identifier de manière unique chaque enregistrement d'une table.

Dans PARTICIPANT, IdParticipant identifie un seul participant : deux participants différents ne doivent pas posséder le même identifiant.

◈Exemple

PARTICIPANT(IdParticipant, Nom, Prenom, Telephone)

✓À retenir

Une clé primaire doit permettre d'identifier un et un seul enregistrement.

✍️À toi de jouer

On veut identifier chaque participant. Les règles indiquent que :

  • IdParticipant est attribué une seule fois ;
  • plusieurs participants peuvent avoir le même nom ;
  • un numéro de téléphone peut être modifié.

Quel champ choisis-tu comme clé primaire ? Justifie.

✓ Vérifier ma réponse

IdParticipant, car il est garanti unique et stable pour identifier un participant.

⚠️Attention

Ne pas choisir automatiquement « Nom » comme clé : plusieurs personnes peuvent porter le même nom.

Séquence 08

Clé primaire composée

•Cours

Une clé primaire peut être composée de plusieurs champs lorsque leur combinaison est nécessaire pour identifier un enregistrement.

INSCRIPTION(IdParticipant#, IdAtelier#, DateInscription)

La combinaison IdParticipant + IdAtelier identifie une inscription. Aucun des deux champs ne suffit seul.

◈Exemple

Règle : un participant ne peut être inscrit qu'une seule fois au même atelier.

INSCRIPTION(IdParticipant#, IdAtelier#, DateInscription)

Les deux champs forment ensemble la clé primaire. IdParticipant seul ne suffit pas, car un participant peut s'inscrire à plusieurs ateliers. IdAtelier seul ne suffit pas, car un atelier accueille plusieurs participants.

✍️À toi de jouer

Dans INSCRIPTION, explique pourquoi IdParticipant seul ne suffit pas, puis pourquoi IdAtelier seul ne suffit pas. Quelle combinaison identifie finalement une inscription ?

✓ Vérifier ma réponse

Un participant peut s’inscrire à plusieurs ateliers, donc IdParticipant se répète. Un atelier accueille plusieurs participants, donc IdAtelier se répète. Le couple (IdParticipant, IdAtelier) identifie l’inscription.

⚠️Attention

Ne jamais inventer une clé composée uniquement pour montrer la notion ; elle doit être imposée par l'identification logique de l'enregistrement.

Séquence 09

Clé étrangère

•Cours

Une clé étrangère est un champ qui fait référence à la clé primaire d'une autre table. Elle permet d'établir un lien entre deux tables.

SALLE
  • CodeSalle
  • NomSalle
  • Etage
POSTE
  • CodePoste
  • Marque
  • Etat
  • CodeSalle#
SALLE ↔ POSTE PK → FK

◈Exemple

SALLE(CodeSalle, NomSalle, Etage)

POSTE(CodePoste, Marque, Etat, CodeSalle#)

CodeSalle# dans POSTE indique la salle dans laquelle le poste est installé.

✍️À toi de jouer

Règle : « chaque poste est installé dans exactement une salle ; une salle peut contenir plusieurs postes ». Où faut-il mémoriser la référence qui permet de connaître la salle d’un poste : dans SALLE ou dans POSTE ? Justifie.

✓ Vérifier ma réponse

Dans POSTE, sous forme de référence vers SALLE. Plusieurs postes peuvent alors porter la même référence de salle.

⚠️Attention

Une clé étrangère n'identifie pas forcément l'enregistrement de sa propre table et peut se répéter.

Séquence 10

Lire les types de relations entre tables

•Cours

Les règles de gestion permettent de déterminer le nombre d'enregistrements pouvant être associés entre deux tables.

  • un-à-un : un élément A correspond au plus à un élément B, et inversement ;
  • un-à-plusieurs : un élément A peut correspondre à plusieurs éléments B, mais chaque B ne correspond qu'à un A ;
  • plusieurs-à-plusieurs : plusieurs A peuvent être associés à plusieurs B.
Un-à-unETUDIANT ─ DOSSIER_SCOLAIREau plus un dossier individuel par étudiant
Un-à-plusieursSALLE ─ POSTEune salle contient plusieurs postes
Plusieurs-à-plusieursPARTICIPANT ─ ATELIERnécessite une table d’association

◈Exemples

  • un-à-un : un étudiant possède au plus un dossier scolaire individuel et chaque dossier scolaire concerne exactement un étudiant ;
  • un-à-plusieurs : une salle peut contenir plusieurs postes, chaque poste appartient à une seule salle ;
  • plusieurs-à-plusieurs : un participant peut s'inscrire à plusieurs ateliers et un atelier accueille plusieurs participants.

✍️À toi de jouer

Associe chaque situation à un-à-un, un-à-plusieurs ou plusieurs-à-plusieurs.

A. Un étudiant possède au plus un dossier scolaire ; un dossier concerne un seul étudiant. B. Une salle contient plusieurs postes ; un poste appartient à une seule salle. C. Un participant suit plusieurs ateliers ; un atelier accueille plusieurs participants.

✓ Vérifier ma réponse

A → un-à-un. B → un-à-plusieurs. C → plusieurs-à-plusieurs.

⚠️Attention

Le type de relation se déduit des règles de gestion, pas du nom des tables.

Séquence 11

Transformer une relation plusieurs-à-plusieurs

•Cours

Une relation plusieurs-à-plusieurs doit être représentée à l'aide d'une table intermédiaire lorsque l'on veut mémoriser les associations entre les deux tables.

PARTICIPANT↔ATELIER
↓
PARTICIPANT→INSCRIPTION
(IdParticipant#, IdAtelier#, DateInscription)←ATELIER

◈Exemple

PARTICIPANT(IdParticipant, Nom, Prenom, Telephone)

ATELIER(IdAtelier, Libelle, DateAtelier, Capacite)

INSCRIPTION(IdParticipant#, IdAtelier#, DateInscription)

INSCRIPTION représente l'association réelle entre un participant et un atelier. DateInscription décrit cette association et appartient donc à INSCRIPTION.

✍️À toi de jouer

Un participant peut s’inscrire à plusieurs ateliers et un atelier peut recevoir plusieurs participants. Pour chaque inscription, on mémorise sa date. Propose la table supplémentaire nécessaire, ses champs et sa clé primaire.

✓ Vérifier ma réponse

INSCRIPTION(IdParticipant#, IdAtelier#, DateInscription), avec la clé primaire composée (IdParticipant#, IdAtelier#).

⚠️Attention

Ne pas placer une liste d'ateliers dans PARTICIPANT ou une liste de participants dans ATELIER.

Séquence 12

Représentation textuelle d'une BDR

•Cours

La représentation textuelle décrit chaque table en indiquant son nom et la liste de ses champs.

Convention du programme : - la clé primaire est soulignée ; - chaque clé étrangère est suivie du symbole #.

◈Exemple

SALLE(CodeSalle, NomSalle, Etage)

POSTE(CodePoste, Marque, Etat, CodeSalle#)

PANNE(CodePanne, DatePanne, Description, CodePoste#)

✍️À toi de jouer

Écris la représentation textuelle du parc informatique à partir de ces règles : une salle est identifiée par CodeSalle ; un poste est identifié par CodePoste et appartient à une salle ; une panne est identifiée par CodePanne et concerne un poste.

✓ Vérifier ma réponse

SALLE(CodeSalle, NomSalle, Etage)

POSTE(CodePoste, Marque, Etat, CodeSalle#)

PANNE(CodePanne, DatePanne, Description, CodePoste#)

⚠️Attention

Ne jamais utiliser # sur une clé primaire uniquement parce qu'elle participe à un lien ; # signale son rôle de clé étrangère dans la table où elle apparaît.

Séquence 13

Vérifier la notation des clés

•Cours

Une représentation textuelle conforme doit permettre d'identifier immédiatement : 1. la clé primaire de chaque table ; 2. les champs qui font référence à une autre table.

✓À retenir

PK = soulignée ; FK = #. Un même champ peut être à la fois membre d'une PK composée et FK dans une table d'association.

✍️À toi de jouer

Une seule écriture respecte les conventions du cours. Laquelle ?

A. POSTE(CodePoste#, Marque, Etat, CodeSalle)

B. POSTE(CodePoste, Marque, Etat, CodeSalle#)

C. POSTE(CodePoste, Marque, Etat, CodeSalle#)

D. POSTE(CodePoste#, Marque, Etat, CodeSalle#)

✓ Vérifier ma réponse

B. CodePoste est la clé primaire : elle est soulignée. CodeSalle est une clé étrangère : elle porte #.

⚠️Attention

Dans INSCRIPTION, les champs de la clé composée gardent aussi le symbole # car ils restent des clés étrangères.

Séquence 17

Définition d'une contrainte d'intégrité

•Cours

Une contrainte d'intégrité est une règle que les données doivent respecter afin de préserver la cohérence de la base.

Dans ce chapitre, on distingue : - les contraintes de table ; - les contraintes de domaine ; - l'intégrité référentielle.

Contrainte de table

Identification et unicité des enregistrements.

Contrainte de domaine

Valeurs autorisées : type, taille, intervalle, liste.

Intégrité référentielle

Une FK doit référencer une PK existante.

✍️À toi de jouer

Classe chaque règle : contrainte de table, contrainte de domaine ou intégrité référentielle.

A. Deux pannes ne peuvent pas avoir le même CodePanne. B. Capacite doit être comprise entre 5 et 30. C. CodeSalle# d’un poste doit désigner une salle existante. D. Etat doit appartenir à une liste de valeurs autorisées. E. Deux étudiants ne peuvent pas avoir le même IdEtudiant. F. IdMedecin# d’une consultation doit désigner un médecin existant.

✓ Vérifier ma réponse

A → table. B → domaine. C → référentielle. D → domaine. E → table. F → référentielle.

⚠️Attention

Ne pas confondre « contrainte » et « commande SQL » : ici on étudie d'abord la règle métier et sa signification.

Séquence 18

Contrainte de table

•Cours

Une contrainte de table impose une règle portant sur l'identification ou l'unicité des enregistrements d'une table.

Exemple : deux pannes différentes ne doivent pas posséder le même CodePanne si CodePanne est la clé primaire.

✍️À toi de jouer

La clé primaire de PANNE est CodePanne. Examine ces lignes :

CodePanne DatePanne Description
P01 10/09/2026 Écran noir
P02 11/09/2026 Réseau absent
P01 12/09/2026 Clavier bloqué

Indique la ligne fautive, la règle violée et une correction possible.

✓ Vérifier ma réponse

La troisième ligne est fautive car P01 existe déjà. La contrainte d’unicité de la clé primaire est violée. Il faut attribuer un CodePanne différent si c’est réellement une nouvelle panne.

⚠️Attention

Ne pas répondre seulement « erreur de clé primaire » : l'élève doit localiser et justifier.

Séquence 19

Contrainte de domaine

•Cours

Une contrainte de domaine limite les valeurs autorisées pour un champ : nature de la valeur, taille, intervalle ou ensemble de valeurs possibles.

◈Exemple

Dans ATELIER, si la règle précise Capacite comprise entre 5 et 30, une valeur 42 viole la contrainte définie pour ce champ.

✍️À toi de jouer

Règles : Capacite ∈ [5,30] et Etat ∈ {En service, En panne, Maintenance}. Quelles valeurs sont invalides ?

  • Capacite = 18
  • Capacite = 42
  • Etat = Maintenance
  • Etat = Disponible
  • Capacite = 5
✓ Vérifier ma réponse

42 est invalide pour Capacite. Disponible est invalide pour Etat. Les autres valeurs respectent les règles données.

⚠️Attention

Ne jamais déclarer une valeur invalide sans citer la règle de domaine donnée dans l'énoncé.

Séquence 20

Intégrité référentielle

•Cours

L'intégrité référentielle impose qu'une valeur de clé étrangère corresponde à une valeur existante de la clé primaire référencée.

◈Exemple

Si POSTE contient CodeSalle# = S09, alors SALLE doit contenir un enregistrement dont CodeSalle = S09.

✍️À toi de jouer

SALLE contient les codes S01, S02 et S03. POSTE contient :

CodePoste CodeSalle#
PC01 S01
PC02 S03
PC03 S07

Quelle ligne viole l’intégrité référentielle ? Explique précisément.

✓ Vérifier ma réponse

La ligne PC03 viole l’intégrité référentielle : S07 n’existe pas parmi les clés primaires de SALLE.

⚠️Attention

Créer artificiellement une salle inexistante comme seule correction possible ; selon le contexte, la bonne correction peut aussi être de corriger la valeur FK erronée.

Séquence 25

Méthode de validation d'une BDR

🧭Méthode

Pour contrôler une BDR : 1. lire toutes les règles de gestion ; 2. identifier les sujets à mémoriser ; 3. vérifier les tables nécessaires ; 4. vérifier la PK de chaque table ; 5. vérifier les relations ; 6. vérifier les FK ; 7. vérifier les contraintes de domaine et de table ; 8. vérifier qu'aucune règle ne nécessite une information absente ; 9. vérifier qu'aucune information n'est placée dans une table qu'elle ne décrit pas.

1Règles de gestion2Tables3Clés primaires4Relations5Clés étrangères6Contraintes7Vérification finale

✍️À toi de jouer

Valide le modèle Hôtel simplifié en suivant la méthode affichée. Vérifie successivement : tables, clés primaires, relations, clés étrangères et emplacement des champs. Donne une phrase de conclusion.

✓ Vérifier ma réponse

Le modèle est cohérent avec les règles annoncées : CLIENT et CHAMBRE possèdent leur propre clé primaire ; RESERVATION possède NumReservation et référence un client et une chambre ; DateDebut et DateFin décrivent la réservation. Conclusion : modèle valide dans le périmètre simplifié annoncé.

⚠️Attention

Commencer par les clés avant d'avoir lu les règles de gestion.

Séquence 26

Méthode de correction d'une structure

🧭Méthode

  1. Repérer la règle non représentée ou violée.
  2. Localiser la cause structurelle.
  3. Choisir l'action minimale : ajouter/déplacer/supprimer un champ, ajouter une FK, modifier une PK, créer une table.
  4. Réécrire la représentation.
  5. Vérifier toutes les règles après correction.

✍️À toi de jouer

Structure proposée : PARTICIPANT(IdParticipant, Nom, IdAtelier#) et ATELIER(IdAtelier, Libelle). Or un participant peut suivre plusieurs ateliers, un atelier reçoit plusieurs participants et on mémorise DateInscription. Reconstruis la structure.

✓ Vérifier ma réponse

PARTICIPANT(IdParticipant, Nom, …), ATELIER(IdAtelier, Libelle, …), INSCRIPTION(IdParticipant#, IdAtelier#, DateInscription).

⚠️Attention

Faire une modification qui règle une question mais casse une autre règle de gestion.

Règles : un élève est identifié par IdEleve. Un projet est identifié par CodeProjet. Un élève peut participer à plusieurs projets et un projet peut réunir plusieurs élèves. Pour chaque participation, on mémorise le rôle de l’élève.
